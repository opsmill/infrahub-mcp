Tool call errors now follow the MCP specification and FastMCP's own error mapping:

- A call with invalid arguments returns a tool result with `isError: true` that carries the validation message, instead of a JSON-RPC `-32603 Internal error`.
- In OIDC mode, a call that the token's scopes do not allow returns a tool result with `isError: true` that names the missing scopes, instead of a JSON-RPC `-32603 Internal error`.
- A call to an unknown tool returns JSON-RPC `-32602`, as SEP-2164 requires, instead of `-32001`.
- When Infrahub is unreachable or rejects the credentials, a tool call now returns the message with a remediation hint, such as "Check that the instance is running", instead of the raw Infrahub SDK message. When Infrahub is not responding, the tool call now prefixes the raw SDK message with "Infrahub is not responding".
- The server's error-handling middleware logs a tool call error at `WARNING` level instead of `ERROR` level, so an error that FastMCP has already logged at `ERROR` level no longer produces a second `ERROR` line.
