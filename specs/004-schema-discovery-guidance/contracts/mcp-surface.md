# Contract: Changes to the MCP Surface

Everything the server sends to a client that changes with this feature. Nothing listed here is removed or renamed.

## Tools

| Tool | Change | Spec |
| --- | --- | --- |
| `get_schema` | Description: states it is the first step; drops "Prefer reading the `infrahub://schema` resource"; states that the listed filter keys are also GraphQL arguments of the kind's query, not a `filters` argument. Name, arguments and output unchanged. | FR-006, FR-011, FR-017 |
| `get_nodes`, `search_nodes` | Description and `kind`/`filters` parameter descriptions name `get_schema` / `get_schema(kind=...)`. The `get_nodes` `filters` description states that in `query_graphql` the same keys go directly on the kind's query. | FR-004, FR-017 |
| `query_graphql` | Description names `get_schema` and states the filter syntax with one example. When Infrahub rejects a query with `Unknown argument 'filters'`, the error remediation names the mistake and shows the correct form for the kind in the query. | FR-004, FR-007, FR-016 |
| `node_upsert`, `mutate_graphql` (write mode only) | Description and parameters name `get_schema`. | FR-004 |
| `list_resources`, `read_resource` | New, only when `INFRAHUB_MCP_RESOURCES_AS_TOOLS=true`. Generated by FastMCP `ResourcesAsTools`. Annotated read-only, no `"write"` tag. | FR-012, FR-014 |

## Error remediation for a `filters` argument in GraphQL

Applies when `client.execute_graphql` raises `GraphQLError` and one of its `errors[].message` values contains `Unknown argument 'filters'`. Every other `GraphQLError` keeps the current remediation.

Target remediation, where `<Kind>` is the first top-level field of the parsed query (the query is already parsed for the mutation check in `gql.py`), or `DcimDevice` when the query has no top-level field:

```text
Infrahub GraphQL has no "filters" argument. Put the filter keys directly on the kind's query, for example:
  <Kind>(name__value: "atl1") { count edges { node { id } } }
The keys are the ones get_schema(kind="<Kind>") lists under "filters"; in get_nodes the same keys go in the filters argument.
```

Tests (SC-006): a mocked `GraphQLError` with `Unknown argument 'filters' on field 'Query.LocationSite'` and the query `{ LocationSite(filters: {name__value: "x"}) { count } }` returns a remediation that contains `LocationSite(name__value:`; any other `GraphQLError` returns the existing remediation.

Rule checked by a unit test (SC-002): no tool description, parameter description or error remediation names an `infrahub://` URI unless it also names a tool the assistant can call for that step with the setting off. For the GraphQL schema (`infrahub://graphql-schema`, referenced in `gql.py:42` and `write.py:113`), that tool is `get_schema(kind=...)`, which returns the kind's attributes and relationships.

## Resources

| URI | Kind | Change | Spec |
| --- | --- | --- | --- |
| `infrahub://schema` | static resource | Unchanged: kind catalog of the default branch. | - |
| `infrahub://schema{?branch}` | new template | Kind catalog of the given branch. | FR-010 |
| `infrahub://schema/{kind}{?branch}` | template (was `infrahub://schema/{kind}`) | Optional branch. `infrahub://schema/{kind}` without a branch still works. | FR-010 |
| `infrahub://graphql-schema`, `infrahub://branches` | unchanged | Readable through `read_resource` when the setting is on. `infrahub://graphql-schema` stays on the default branch (out of scope, spec Assumptions). | FR-012 |

Rule checked by a unit test (SC-004): for the same kind and branch, the resource and `get_schema` return the same text.

## Server instructions

New, in four variants (read-only on or off, resource tools on or off). See [server-instructions.md](./server-instructions.md).

## Configuration

| Environment variable | Type | Default | Effect |
| --- | --- | --- | --- |
| `INFRAHUB_MCP_RESOURCES_AS_TOOLS` | bool | `false` | Adds `list_resources` and `read_resource` to the tool list. |

## Compatibility

No existing tool, argument, resource URI or prompt name changes, so existing callers are not broken. Release label: `changes/minor` (new setting, new resource templates, new server instructions).
